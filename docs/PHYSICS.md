# 物理互动：重力、甩动、撞边框

> 口径（用户明确要求）：**重力永远在，宠物常态就待在屏幕下方**。
> 「甩动 / 撞边框」是给它加碰撞能力 —— 甩出去会飞、撞到边框会弹、最后被重力拉回下方停稳。
> 失重（往上飘）只是默认关闭的实验开关，不是常态。

## 1. 它怎么动

| 行为 | 机制 | 你能看到的 |
|---|---|---|
| 常态待在下方的地面上 | 重力 2200 px/s² + 空气阻尼，贴底后自动「睡」（停止每帧移动窗口，不空转 CPU） | 掉下去 → 弹几下（1413 → 683 → 353 → 185 → 94 px/s）→ 稳住 |
| 拖动 = 甩 | 松手时取**最近 120ms** 的指针采样算速度，交给物理体 | 往左下甩，实测峰值 **9084 px/s** |
| 撞边框 | 四边（工作区上下左右，已排除任务栏）法向反弹，`RESTITUTION=0.55`；切向保留 `0.88` | 撞右边 3666 px/s、撞底 1079 px/s、撞左 1123 px/s |
| 撞击反馈 | 撞击那条边冒一簇火花 + 宠物朝内侧抖 7px（120ms 后复位） | 撞墙瞬间看得见 |
| 静止 | 两轴速度都低于阈值且贴边 → `sleep()`，窗口不再被每帧写 geometry | 日志：「物理：停稳在 (x,y)，不再每帧移动窗口」 |
| 失重实验（默认关） | 重力反向 900 px/s²，往上飘、贴顶悬停 | 右键菜单「失重实验」 |

参数都在 [companion/petphysics.py](../companion/petphysics.py) 顶部，是可直接断言的常量：

```python
GRAVITY = 2200.0      AIR_DRAG = 0.55     RESTITUTION = 0.55
WALL_FRICTION = 0.88  MIN_BOUNCE = 45.0   SLEEP_SPEED = 18.0
MAX_SUBSTEP = 1/240   # dt 再大也切子步 → 不穿墙
```

**为什么不穿墙**：`Body.step(dt)` 会把 `dt` 切成 ≤1/240s 的子步（上限 64 步）。
实测把 `dt` 给到 1.0 秒、初速 3000px/s，连续 30 次仍在工作区内。

**坐标系**：屏幕像素、y 向下；`Body` 只跟踪窗口左上角。
工作区用 `SystemParametersInfoW(SPI_GETWORKAREA)` 拿（纯 ctypes 标准库），拿到的是**任务栏之上**的区域。

## 2. 怎么用

* 拖动宠物 → 松手就是甩；甩得越快飞得越远。
* 右键菜单：
  * **甩动 / 撞击边框（重力常开）** —— 关掉就只剩「跟着你拖」。
  * **失重实验：飘到上面（默认关）** —— 打开才往上飘。
* 撞击次数、速度、位置都会写进 `~/.dsh/aoqi-pet/aoqi-pet.log`。

## 3. 验证

```bash
python test/pet-physics.py     # 13 项：物理数学（不需要 GUI / DSH）
python test/physics-live.py    # 真机：拉起隔离实例，用 Win32 量真实窗口矩形
python test/physics-live.py --with-antigravity   # 顺带验失重开关
```

真机实测（1920×1200，125% 缩放，任务栏之上工作区底边 = 1140；连跑 3 次全绿）：

```
[相位 A] 重力：从 (240,0) 起手 → 8 秒内停稳=True，2.0~2.8 秒停稳
  采样 62 次  y: 416 → 750   y范围[416,750]   峰值 1706px/s
  撞边框：bottom 1413 → 683 → 353 → 185 → 94px/s
  最终落点 y=750 = 1140 - 390（窗口高）      ← 底边正好贴在工作区下沿
[相位 C] 合成鼠标甩动（抓宠物身体快速往左下甩）
  运动幅度 881~1048 逻辑px   峰值 8960~9084px/s   2.1~2.8 秒停稳
  撞边框：right 3666 / bottom 1079 / left 1123 px/s
  最终落点 y=750（又被重力拉回下方）
=> 9/9 项通过，连跑 3 次全部通过
```

> **坐标口径（别把两套数字混着看）**：桌宠进程自己日志里的「停稳在 (240,600)」是它**自己的坐标系**
> （它是 DPI 不自知的 Tk 进程，认为工作区是 1536×912、窗口 216×312）；
> 验证脚本是 DPI 感知的独立进程，`GetWindowRect` 报的是 1920×1200 那一套（窗口 216×390、落点 y=750）。
> 两者说的是**同一个物理位置**：600 × 1.25 = 750，而两边的底边都正好等于任务栏上沿。
> 断言用的是「窗口底边 = 工作区底边」，与用哪套坐标无关。

## 4. 过程中抓到的两个真 bug（都有证据）

1. **新物理体是「睡着」的** → 重力模式启动时完全不落。
   证据：第一次真机跑，相位 A 四秒半里窗口 `y: 0 → 0`，日志只有 `物理体：…` 两行。
   修法：`build_body()` 里 `mode != none` 就 `wake()`。
2. **`overrideredirect` 窗口在 mainloop 前 `winfo_x()` 返回 0** → 物理体把窗口从 240 硬拽到 0，
   看起来像「横向漂移」。
   证据（调试日志）：`物理体：… 起点=(0,0)` 紧跟着 `[debug] 拍1 body=(0.0,0.0) 窗口=(240,0)`。
   修法：窗口位置**自己记账**（`self.win_pos`，凡是我们调 `geometry` 的地方都更新它），
   不再信 `winfo_x()/winfo_y()`；`--physics-debug` 保留了逐帧日志以便复查。

顺带一个测量教训：**验证脚本自己必须声明 DPI 感知**，否则 `GetWindowRect` 返回 125% 缩放下的虚拟坐标
（1536×960），和 Tk 用的逻辑坐标不是一套口径，会得出「没落到底」的**假失败**。
现在用 `GetDpiForWindow/96` 换算，脚本里写明了。

## 5. 诚实的边界

* **不做形变**：Tk 图片只能整数缩放，所以「撞墙压扁/拉伸」做不到，反馈是位移抖动 + 火花。
* **只按主显示器工作区**：多显示器拼接场景没处理（`SystemParametersInfoW` 只给主屏工作区）。
* **手动拖动时不跑物理**（`dragging` 让位），松手才把速度交给物理体 —— 这是刻意的，否则会和鼠标抢窗口。
* 位置每 2 秒回写一次设置文件（以及停稳时写一次），所以关掉桌宠再开还在原位；不会每帧写盘。
